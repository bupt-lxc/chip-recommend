# 新场景小规模开放搜索：未通过全链路验收

运行日期：2026-10-22；汇总核验：2026-10-26。使用真实 Hermes 0.19.0、Tavily 和 qwen3.8-flash，不指定目标芯片。两个场景各生成 10 条查询，每查询纳入 1 个结果，主要候选上限各 4 个。独立容器只读加载当前代码，使用正式库的隔离副本。

整轮没有总时限，两组合计约 **63 分钟**。本次测试进程保留页面单请求 20 秒、后台模型单请求 120 秒及原有重试保护；正式运行配置未修改。

## 主要发现

1. **搜索接口已能工作，瓶颈更多在下游。** 规格队列命中 H100、MI300X、昇腾910B、思元590相关页面，兼容队列命中 PyTorch 发布说明、昇腾适配说明、Gaudi 2 发布说明。一个 EET 页面读取超时。搜索成功率表示接口正常返回；不能据此认定来源质量、时效性或新芯片发现率合格。规格队列 4 页仅 1 个厂商官网，查询仍偏已有型号。
2. **规格运行的致命问题已定位到上下文协调。** 同一 H100/vendor 身份候选先后被普通关联任务、身份依赖任务使用，复核绑定中的 `identity_context` 从 `{}` 变成未验证的依赖线索，触发 `model_input_conflict: review/execution_binding`。绑定保护应保留，需要修复调度与缓存的协调。期间 30 条候选曾处于接受状态，其中 10 条属于规格，但没有终态比较，不能计为有效更新。
3. **“新实体”存在误计。** 兼容运行报告 2 个临时新实体；其中 `Huawei / Ascend 910B` 对应基线 id=79 的 `Huawei / 昇腾910B`，是英文别名漏匹配。`Intel / Gaudi 2` 在本次基线未找到。不能把两者都报成新芯片发现。兼容主域最终 3 条均为软件栈字段，模型专属兼容关系没有形成最终有效候选；另有 6 条有效字段属于身份域。
4. **小 URL 数仍对应较大的模型工作量。** 后台记录 125 次调用尝试，109 次完成、9 次读取超时、7 次响应结构拒绝；Hermes SDK 另记 16 次 API 调用。规格筛选单次输入从约 5.4 万增至 7.7 万 token。修订响应缺完整候选、中文单位与规范单位不一致、快照哈希错误及重复提取冲突，也造成拒绝或未解析。

## 建议顺序

先修复身份依赖与复核缓存的上下文协调，再完善受控别名匹配并保留容量、封装等变体差异。之后用这些新保存正文排查输出结构、单位和元数据问题，同时减少重复 Skill 上下文、评估长页输出规模与请求耗时。本轮不修改这些业务规则。

正式数据库哈希、隔离来源库哈希及业务表行数均保持不变；现网镜像与启动时间未变，没有正式业务/溯源写入，没有启用发布或心跳。离线核对 125 条后台请求与 7 份正文/原始页面哈希，均与保存产物一致。首次漏带生成 Skill 副本的两次预检失败也已保留，它们未发出搜索或模型请求。

详细统计、运行 ID、冲突差异及产物路径见[机读记录](2026-10-22-small-open-web-e2e.json)。
